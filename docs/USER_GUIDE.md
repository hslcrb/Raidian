# Raidian 사용자 가이드

> 가장 중요한 한 줄: **커밋은 로컬의 기록**, **푸시는 서버로 전송**입니다. 🍒

## 0. 시작하기

1. Windows에는 Git for Windows를 먼저 설치하고, `git --version`이 동작하는지 확인합니다. GitHub 연동이 필요하면 `gh` CLI도 설치하고 `gh auth login`을 실행합니다.
2. Python 실행은 `python -m raidian gui`, 포터블 Windows 빌드에서는 `Raidian.exe`입니다.
3. `폴더 열기`로 `.git`이 있는 프로젝트(또는 그 하위 폴더)를 선택합니다. 새 프로젝트면 `새 저장소`를 누르고 빈 폴더를 지정합니다.
4. 변경 파일과 현재 브랜치를 확인합니다. 커밋 메시지를 직접 입력하거나 비워둡니다.
5. **커밋**을 눌러 로컬에 기록합니다. 원격으로 보낼 때만 **푸시**를 누릅니다.

## 1. 화면 지도

- 상단 버건디 배너: Raidian 정체성 및 탐색 맥락.
- 경로 표시: 현재 열려 있는 저장소의 위치. 디렉터리를 바꾸려면 `폴더 열기`.
- 액션 라인: 푸시/가져오기/브랜치 생성·전환/no-ff 병합/원격/GH.
- 정보 패널: 현재 브랜치와 수정 파일 수.
- 두 개의 표: 왼쪽 파일 변경, 오른쪽 커밋 이력.
- 하단 커밋 입력: 한글 커밋 메시지, **커밋**, **커밋 + 푸시**.
- 상태 바: 처리 중/완료/실패 및 선택된 이력의 의미 설명.

폭이 좁아지면 버튼이 여러 줄로 재배치되고 이력 표는 아래로 이동합니다. 파일 상태 표시는 Git의 두 글자(`??`, `M`, `A`, `D`, `R`)를 그대로 사용하므로 Git Bash와 비교하기 쉽습니다.

## 2. 잘 쓰는 Git 용어

| 버튼/용어 | 대응되는 Git 행동 | 기억할 점 |
| --- | --- | --- |
| 새 저장소 | `git init -b main` | 기존 저장소는 `폴더 열기` 사용 |
| 커밋 | `git add --all; git commit` | 기본적으로 **전체 변경** 포함. 민감 파일 먼저 검사 |
| 푸시 | `git push` / `git push -u` | 인증 및 네트워크 필요 |
| 가져오기 | `git fetch --all --prune` | 파일을 즉시 병합하지 않음 |
| 브랜치 전환 | `git switch` | 작업 트리가 깨끗해야 함 |
| 병합 | `git merge --no-ff --no-edit` | 가능한 경우에도 별도의 병합 커밋 보존 |
| 이력 복사 | `git cherry-pick SHA` | 다른 브랜치에 **새 커밋** 생성 |
| 변경 되돌리기 | `git revert SHA` | 삭제가 아니라 안전한 **역방향 커밋** 추가 |

## 3. 사용 예시

### A. 한글 이름의 문서 업데이트

`한글로 만든 문서.md`를 수정 → 새로고침 → 목록에서 파일 확인 → 메시지 입력 `docs: 한글 가이드 보강` → `커밋` → 필요하면 `푸시`.

### B. 실수로 메시지 없이 커밋

메시지가 비어 있어도 파일 구성을 분석해 `docs: 문서 업데이트`, `feat: 새 파일 추가`, `chore: 변경 사항 업데이트` 등의 **예측 가능한 문구**를 사용합니다. Git에서 실제 변경이 없으면 빈 커밋을 만들지 않습니다. 이 기능은 LLM 없이 작동하므로 인터넷이 필요 없습니다.

### C. 소규모 작업 분기

`브랜치 만들기`에서 `feature`와 `korean-ui`를 입력하면 `chatgpt-extrahigh/feature/korean-ui`를 만듭니다. `/`로 나뉜 이름은 **표시용 네임스페이스**이고, 실제 분기 시점은 `git switch -c`에 전달한 커밋입니다. Git에서는 `foo`와 `foo/bar`라는 브랜치를 동시에 둘 수 없으므로 항상 이 규칙을 고려하세요.

### D. 특정 과거 변경만 취소

커밋을 선택하고 **선택 커밋 되돌리기(revert)** → 내용을 확인 → 확인 버튼. 새 역커밋이 기록됩니다. 협업 중인 브랜치에서 `git rebase -i`로 특정 커밋을 역사에서 지우는 위험한 작업은 GUI에서 지원하지 않습니다.

## 4. 키보드

- `Ctrl+O` 저장소 열기 · `F5` 새로고침 · `Ctrl+Enter` 커밋 · `Ctrl+Shift+Enter` 커밋+푸시.
- `Alt+B` 계층 브랜치 만들기 · `Alt+P` 푸시.
- pill 버튼에 Tab으로 포커스를 옮겨 Enter/Space로 작동할 수 있습니다.
- 화면읽기 도구는 Tk/OS 조합에 따라 Canvas 버튼 접근성이 제한될 수 있습니다. **완전한 스크린리더 지원을 보장하지 않으며** 더 나은 네이티브 대안을 검토하고 있습니다.

## 5. 실패 시

- `git 실행 파일이 없습니다`: Git for Windows 설치 및 PATH 등록 확인 후 프로그램 재실행.
- `변경 사항을 커밋하거나 보관`: 의도치 않은 파일이 덮이지 않도록 브랜치 이동을 막은 것입니다.
- `Not a git repository`: Git 저장소 경로를 열거나 새 저장소 생성.
- 인증 오류: 터미널에서 `git push` 또는 `gh auth status`를 검사하세요. 앱에 비밀번호를 붙여 넣지 마세요.
- 병합 충돌: 자동 덮어쓰기 하지 않습니다. Git Bash/코드 편집기로 충돌 파일을 확인 후 해결해야 합니다.
- 글꼴이 다르게 보임: 운영체제에서 지원하는 한국어 글꼴을 선택합니다. 첨부 파일이 확인되지 않아 커스텀 폰트는 기본 빌드에 없음.

## 6. 배포판 주의사항

Windows 포터블 EXE는 Python 런타임을 내장하도록 설계되지만 **Git/gh/인증 관리 도구는 별도**입니다. `README-PORTABLE.txt`와 SHA256을 함께 확인하세요. 미서명 EXE의 Windows SmartScreen 경고는 출처 확인이 필요하다는 뜻입니다. 서명되지 않은 빌드를 무조건 신뢰하지 마세요.
