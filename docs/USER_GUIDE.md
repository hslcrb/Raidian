# 🌷 루비가 알려주는 레이디안

## 0. 준비할 것

앱 실행용 Windows EXE에는 Python과 Node 설치가 필요 없어요. 소스에서 실행하려면 Node.js 22+와 `npm install`이 필요하고, **모든 경우 Git은 따로 설치**되어야 해요. PR 조회나 생성까지 하려면 [GitHub CLI](https://cli.github.com/)의 `gh auth login`을 이용하세요.

## 1. Git 폴더 열기

레이디안 상단의 **📁 폴더 열기**를 클릭해 기존 Git 폴더를 고르세요. 처음부터 시작한다면 **＋ 새 저장소**를 누르면 Git이 `main` 브랜치를 만듭니다. 화면 위에는 저장소 경로와 활성 브랜치가 표시돼요.

## 2. 변경 파일 살펴보기

좌측 카드에는 파일명과 Git 상태가 나와요.

| 상태 | 뜻 |
|---|---|
| `??` | 아직 추적하지 않은 새 파일 |
| `M` | 수정됨 |
| `A` | 추가됨 |
| `D` | 삭제됨 |
| `R` | 이름 변경됨 |

Git의 상태 문자열은 스테이징 상태와 작업 디렉터리 상태를 각각 보여주는 2글자 코드예요.

## 3. 커밋과 푸시

아래 메시지 상자에 `feat: 첫 페이지 추가`처럼 적고 **커밋하기**를 누르세요. 글을 비우면 변경 종류를 바탕으로 한국어 기본 메시지를 자동으로 만듭니다. **커밋하고 푸시**는 커밋을 성공적으로 마친 후 원격 주소를 확인해 푸시합니다. Git 계정 설정이 없거나 원격이 없으면 오류를 보여줘요. 실패 시 이미 저장된 로컬 커밋을 취소하지 않습니다.

## 4. 여러 작업을 나눠 할 때

**하위 브랜치**에서 `feature` / `first-screen`을 입력하면 `chatgpt-extrahigh/feature/first-screen` 브랜치를 만듭니다. 시작 브랜치는 현재 HEAD 또는 목록 중에서 고를 수 있어요. `/` 계층은 이름 규칙일 뿐 실제 관계는 분기 시점에 결정됩니다.

원래 브랜치로 돌아가서 **병합 · no-ff**를 누르면 Git의 `git merge --no-ff --no-edit`가 실행됩니다. 충돌이 난 경우 사용자가 파일의 충돌 표시를 확인하고 수동으로 해결해야 합니다.

## 5. 과거 이력 복사 또는 특정 시점의 변경 취소

우측 **커밋 기록**에서 커밋을 클릭합니다. **변경 복사**는 cherry-pick으로 예전 변경을 현재 브랜치에 새 커밋으로 적용해요. **커밋 되돌리기**는 revert로 해당 변경의 역연산을 새 커밋에 기록합니다. 공유 이력을 직접 삭제하지 않아요.

## 6. 다른 원격 저장소 연결

**원격 관리**에서 `origin`, `backup`, `upstream`처럼 서로 다른 이름으로 Git URL을 관리할 수 있습니다. 푸시·풀에서 원격을 고를 수 있어요. `fetch`는 모든 원격의 최신 정보를 가져옵니다. 네트워크 연결과 로그인 상태에 따라 작업에 시간이 걸릴 수 있어요.

## 7. 단축키 / 접근성

| 단축키 | 동작 |
|---|---|
| `Ctrl+O` | 저장소 폴더 열기 |
| `F5` | 새로고침 |
| `Ctrl+Enter` | 커밋 |
| `Ctrl+Shift+Enter` | 커밋 후 푸시 |
| `Alt+B` | 하위 브랜치 만들기 |
| `Alt+P` | 푸시 |

포커스 이동은 Tab/Shift+Tab, 버튼 활성화는 Enter/Space로 가능합니다. 안내문은 `aria-live`와 구별 가능한 텍스트로 표시됩니다. Windows 화면 읽기 도구의 실제 호환성은 Windows 실행 QA에서 검증해야 합니다.

## 8. 어려울 때

상단 **새로고침**으로 최신 상태를 확인하고, 명령줄에서 `git status`를 실행하면 충돌 상태를 자세히 볼 수 있어요. 잘못된 결과에 무작정 재시도하지 마세요. Git 경고는 의도적으로 숨기지 않습니다.
